feat: 四项 LiteLLM 路由能力（冷却退避 / 实测延迟 / 成本优先 / 预算限流）

1. 冷却 + 指数退避
- 失败目标进入冷却，连续失败每次翻倍（15s 起，上限 10 分钟）
- 成功即清零，不记仇
- 冷却中的目标在打分前就被过滤，不会靠高分挤回来
- 402/429/404/5xx 与网络错误都算目标故障，会冷却并换下一个

2. 实测延迟路由（auto-latency）
- 按真实观测到的首字延迟排序（指数平滑，0.7 旧 + 0.3 新）
- 未测量过的目标放在中间，既不被饿死也不会贸然排第一
- 取代原来硬编码的厂商速度档（Groq=3 / NVIDIA=0 那种拍脑袋值）

3. 成本优先路由（auto-cost）
- 按每百万 token 单价从低到高，免费模型优先
- 价格表按模型系列匹配，未知模型给中性价

4. 预算与限流
- 每个厂商设每日 token 上限（Groq 20 万 / Cerebras 100 万 / Google 50 万…）
- 从上游 usage 帧读真实 token；没有该帧则按 4 字节≈1 token 估算
- 超预算的厂商在路由时跳过，并在日志页标红显示用量百分比

顺带修掉两个真 bug（由实测暴露）:
- 404 被当成「请求本身有问题」直接返回给用户，实际是
  「这个 id 不支持该端点」，属于目标问题，应换下一个
- OpenRouter 的 :batch / -extended 等变体 id 不是聊天模型，
  会被选中后报 404；已加入 NOT_CHAT 过滤

运行日志页新增健康条：冷却中的目标 + 今日预算用量，超限标红。
